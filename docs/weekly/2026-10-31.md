# 周报：msModeling PD 混部与分离性能边界评估

周报周期：2026-10-26 至 2026-11-01；本次总结截至 2026-10-31。

依据：[完整评估记录](../../experiments/pd_boundary/MSMODELING_PD_EVALUATION_JOURNEY.md)。有明确日期的主要实验集中于 10 月 29—31 日；准备阶段和早期扫描按原文先后顺序回顾，不补造运行日期。

> 本文所有时延、吞吐和显存数字均为解析模型预测。本轮没有进行真实 Ascend 服务压测、真实 W8A8 精度验证或 KV offload/H2D 验证。未完成实验按原始评估文档整理时的快照报告。

## 一、本周工作与交付

围绕“长输出能否摊薄 chunked prefill 对 decode 的干扰，以及 PD 分离何时有收益”，将参数扫描推进为可核验的机制、系统与容量对照。

| 工作项 | 完成内容 | 结果 |
|---|---|---|
| 环境与资源口径 | 固定 Python 3.12.10、msModeling 26.2.0、PyTorch 2.10.0；统一整卡、die、TP 和量化定义 | 后期以 DeepSeek-V4-Flash、Linear W8A8_DYNAMIC 为主，attention/KV 不量化 |
| 开环发压与审计 | 固定原始到达时间，拆分外部 FIFO 与全局准入，记录逐 token、step 和队列轨迹 | TTFT 包含准入等待；检查请求守恒、token 映射与轨迹复现 |
| PD 交接修正 | 复现 D 侧 prompt KV 预留遗漏；以独立 adapter 保留交接状态，D 完整预留 ACK 后释放 P 源 KV | 在修正记账后开展混部/分离对照 |
| 架构与持续负载 | 同总资源 N4 配对，以及每秒 1 请求、600 秒六组对照 | 分开报告窗口结果、排空结果和主机超时 |
| 输出长度机制 | 单 TP8、D batch1、有限 P 冲击，输出 16—8192，逐 token 增长上下文 | 验证有限干扰摊薄，未在受测范围观察到 TPOT 回升 |
| 输入/输出压力 | 32K/4K 输入 × 128/2048 输出四组对照 | 4 组诊断与 4 组正式窗口全部完成并通过审计 |
| 完整排空补跑 | 保持相同 120 请求和到达时刻，补跑 A/C/D | A 完成；C 预测显存超预算停止；D 在原文快照中仍运行 |

系统级 A3 对照共用 8 张整卡、16 个模拟 die：混部为双 TP8，分离为 P/TP8 + D/TP8，各占 4 张整卡。单 TP16 的 reshape 问题仍未修复。

## 二、关键结果与结论

### 1. 有限干扰能摊薄，但长停顿仍然存在

在单 TP8、I32K、实际 D batch1、无 offload 的配对实验中，额外 P 等待总量约 9419.062 ms：

| 输出 token 数 | 带 P 平均 TPOT（ms） | 最大 ITL（ms） |
|---:|---:|---:|
| 16 | 653.103 | 1190.565 |
| 128 | 99.332 | 1190.565 |
| 512 | 43.598 | 1190.565 |
| 2048 | 29.767 | 1190.565 |
| 8192 | 26.316 | 1190.565 |

纯 D 平均成本仅由约 25.165684 ms 增至 25.166367 ms。当前结果符合 `TPOT(O) = C(O) + H/(O−1)`；不能据平均 TPOT 下降推断长 ITL 已消失，也不能外推为任意 batch、上下文或持续负载下均单调改善。

### 2. 固定 4P+4D 分离改善连续性，但本轮 TTFT 与 E2E 更差

在同为 8 张整卡、I32K、budget4096、N4、0.4 请求/秒、O128 的对照中：

| 架构 | 平均 TTFT（s） | 平均 TPOT（ms） | 平均 E2E（s） |
|---|---:|---:|---:|
| 混部 | 11.773 | 73.473 | 21.104 |
| 分离，交接 0 ms | 19.876 | 25.166 | 23.072 |
| 分离，交接 200 ms | 19.876 | 26.741 | 23.272 |

200 ms 为诊断假设。当前契约由 P 发首 token，传输影响第二个及之后的 token；首个交接间隔约 225 ms。分离的阶段资源分配加重了 P 排队，不能将所有差异只归因于干扰隔离。四组分离案例实际 D batch 峰值仍为 1。

### 3. 排空完成不代表能够稳定承载每秒 1 请求

600 秒窗口内，混部 O16/O128 分别完成 121/92 个请求；四组分离均完成 63 个。分离虽最终各完成 600/600，但停止到达后仍需约 5071—5074 个模拟秒排空；混部两组因主机 6 小时超时，未取得最终全队列时延。

### 4. 缩短输入能建立更高 D 压力，长输出还会改变聚批

四组均为每秒 1 请求、120 请求，以下仅统计固定 `[0,120)` 窗口：

| 组别 | 输入/输出 | 实际 D batch 峰值/引擎 | 窗口完成数 | 可见完整 ITL 均值（ms） |
|---|---|---:|---:|---:|
| A | 32K/128 | 12 | 0 | 1190.478 |
| B | 4K/128 | 43 | 33 | 608.952 |
| C | 32K/2048 | 12 | 0 | 1190.478 |
| D | 4K/2048 | 60 | 0 | 658.919 |

缩短输入使窗口截止前拿到首 token 的请求由 24/120 增至 119/120。B→D 的输出延长进一步增加 D batch，但 ITL 均值也增加约 50 ms。4K 输入减少了初始 KV，batch60 不能直接外推到 32K 输入。

## 三、当前问题与实验状态

| 项目 | 状态与影响 |
|---|---|
| A：32K/128 完整排空 | 120/120 完成；全量审计通过；平均 TPOT 与全体 ITL 均值均为 1042.942 ms，前 120 秒 token/调度/队列精确复现 |
| B：4K/128 | 本轮未补跑；原窗口仅 33/120 完成，完成者 TPOT 464.848 ms，不能作为全队列同口径对照 |
| C：32K/2048 完整排空 | 模拟 365.430 秒时以 MODEL_MEMORY_INVALID 停止，0/120 完成；失败混合 batch 预测占用 65.265 GiB/die，超过 64 GiB/die，缺少 1.265 GiB/die |
| D：4K/2048 完整排空 | 原文最近核验快照约 508.0 模拟秒、2050 step、0/120 完整完成，尚无完整请求 TPOT |
| 显存复现 | 时序与轨迹哈希可复现，但串行复跑最小余量仍相差约 0.243735 GiB，原因未查明 |
| 模型边界 | 完整驻留 V4 缓存账本、真实设备校准和 offload/H2D 尚未验证，不能将解析曲线当作生产 SLO 结论 |

C 的失败由权重、KV、临时激活与预留共同构成，属于预测显存超预算，不能直接称为实机 OOM 或仅归因于 KV 占满。原始失败保留，未通过改参数覆盖失败结果。

## 四、下一步计划

1. 跟进 D 组排空，完成后独立重算请求级 TPOT、ITL 和队列守恒；若失败，保留明确的终止原因与形状。
2. 定位 C 组混合 batch 的容量约束，在新实验目录中设计调度/参数对照，保留现有失败证据。
3. 排查显存估计跨进程差异，完善完整驻留缓存和临时激活记账。
4. 在相同总资源下探索 P/D 卡比、budget 和到达率，围绕 TTFT、ITL、完成率的联合目标寻找稳态边界。
5. 以真实 Ascend 测试校准解析结果，再开展 offload/H2D 与真实服务压测验证。

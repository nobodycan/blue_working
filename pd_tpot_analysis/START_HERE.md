# 使用说明：给内部模型的 PD TPOT 分析包

## 这是什么

这不是已经分析过真实数据的报告。本包没有读取你的 aisbench 文件，也没有假设其 JSON/CSV 结构。

交付包含：

```text
pd_tpot_analysis/
  START_HERE.md                         本说明和启动提示词
  SKILL.md                              主 Skill：阶段、门禁、禁止事项
  references/
    DATA_CONTRACT.md                    真实数据到标准化 CSV 的契约
    PROTOCOL.md                         详细分析协议和结论边界
    STAGE_PROMPTS.md                    可以逐条粘贴的分阶段提示词
  scripts/
    analyze_normalized.py               无第三方依赖的标准化数值分析器
```

你需要提供：原始结果目录、相关运行配置/命令，以及可以确认的发压方式。其他信息可以先未知，流程会指出缺口及其影响范围。

## 推荐用法：不要一次让弱模型完成全流程

1. 将整个 `pd_tpot_analysis` 文件夹复制到内部环境，放在原始数据目录之外。
2. 将下面的“首次启动提示词”发给内部模型，填实际路径。
3. 先让其完成阶段 0、1；检查字段映射，尤其是单位和实际 token 数。
4. 再逐条发送 `references/STAGE_PROMPTS.md` 的相应提示词。
5. 每阶段让其写文件保存结果，并维护 STATE.md；换会话时重新读状态和必要附件，不依赖模型记忆。
6. 字段映射和门禁通过后，运行附带分析器，而非让模型临时另写一套 TPOT/统计公式。
7. 最后按统一模板汇总，不让模型把“可能符合”润色成“已经证明”。

不要求模型支持原生 Skill。如果只能聊天，上传附件或把当前阶段所需章节粘贴进上下文即可。若环境支持 Skill，按该环境自己的安装方式加载 SKILL.md，保留附件的相对目录。

## 首次启动提示词

复制并替换 `<...>`，不要将占位符作为实际路径运行：

```text
你是执行人员，不负责迎合我的假设。请严格按分析包执行，不猜字段，不联网，不上传内部数据。

分析包路径：<分析包绝对路径>
原始 aisbench 数据路径：<原始数据绝对路径>
工作产物路径：<与原始目录分开的新目录>
相关运行配置/命令路径：<有则填写，无则写 unknown>

背景：昇腾 A2；PD 混部一台机器；PD 分离两台机器。
计划输入 512；计划输出 512/1024/2048/4096/8192/16384/32768/65536；计划并发 1/4/8/16/32。

先读 START_HERE.md、SKILL.md、DATA_CONTRACT.md 和 PROTOCOL.md。

每阶段必须记录输入、操作、产物、检查、未知项、阻塞影响和下一步。
```

## 运行标准化分析器

### 环境

Python 3.9 或更新版本，只使用标准库。不需要 pandas、numpy、scipy，也不需要联网。

下列命令是模板。`<脚本绝对路径>` 指 `scripts/analyze_normalized.py`；CSV 必须已经按 DATA_CONTRACT.md 生成。不要直接把任意 aisbench JSON 传进去。

### 1. 先自测

```text
python -I "<脚本绝对路径>" self-test
```

自测使用明确标记的数值测试夹具，不是真实压测结果。8 项测试覆盖数值模型、重复记录、时间边界、重复不足、无效配对、加权口径和变长输出限制。

### 2. 验证标准化数据

```text
python -I "<脚本绝对路径>" validate --runs "<runs.csv绝对路径>" --requests "<requests.csv绝对路径>" --out "<全新验证目录>"
```

输出 `validation.json`。退出码 0 表示标准化结构检查通过；退出码 2 表示失败。

注意：结构检查不能证明原始字段语义正确，也不能证明重复运行独立。字段审计仍需完成。

### 3. 主分析

以下示例采用每请求 TPOT 的运行均值作为主指标，并探索性考察 5% 容差。5% 不是已获用户确认的业务标准：

```text
python -I "<脚本绝对路径>" analyze --runs "<runs.csv绝对路径>" --requests "<requests.csv绝对路径>" --out "<全新主分析目录>" --metric request_mean_tpot_ms --bootstrap 5000 --ci 0.95 --seed 20261111 --margin 0.05
```

没有容差标准时删除 `--margin 0.05`，脚本会输出差值与区间，但不评价是否进入容差。

只有能出示“看结果前已经确定容差”的事实依据时，才额外传入 `--margin-prespecified`。该开关是事实标记，不是改善结论的选项。

### 4. 聚合口径敏感性分析

```text
python -I "<脚本绝对路径>" analyze --runs "<runs.csv绝对路径>" --requests "<requests.csv绝对路径>" --out "<全新敏感性目录>" --metric token_weighted_tpot_ms --bootstrap 5000 --ci 0.95 --seed 20261111 --margin 0.05
```

不要把敏感性指标替换成主指标，只因为其更符合预期。若两种口径结论不同，解释实际输出分布和加权差异。

所有输出目录都必须是新的，包括验证目录和分析目录。脚本拒绝覆盖已有目录。失败重试也使用新目录，不先删掉失败证据。

## 脚本会产生什么

| 文件 | 用途 |
|---|---|
| validation.json | 错误、告警、输入哈希、脚本哈希、参数、时间、限制 |
| run_metrics.csv | 每次运行的两种 TPOT 均值、请求分位数、实际输出、失败情况 |
| group_metrics.csv | 每条件的运行等权均值、运行间波动、可用时的区间 |
| comparisons.csv | 同并发同长度的 Δ、相对差、可用时的 CI 和 E、容差标记 |
| fit_diagnostics.csv | 描述性的 A/δ、残差误差、留一长度对比、端点敏感性 |
| fit_residuals.csv | 每个有效长度的预测值与残差 |

空结果文件仅有 `no_rows` 表头，表示该结果不可计算，不是 0。画图和报告时必须处理为空，不得填零。

相对差和失败率在 CSV 中使用比例：0.05 = 5%。`fixed_actual_target` 为明确的 True/False 字符串；不要用“非空字符串就是真”来解析 False。

脚本不自动绘图、不自动生成最终文字报告、不解析未知 aisbench 格式、不宣称因果、不替代实验设计审计。

## 结果阅读顺序

1. 先看 validation.json：有错误就停止对应数值分析；告警逐条解释。
2. 看 run_metrics.csv：失败率、长度、异常运行、真实重复次数。
3. 看 group_metrics.csv：两种部署各自的 TPOT 变化。
4. 看 comparisons.csv：差距是否缩小、区间是否足够窄。
5. 看 fit_diagnostics.csv 和 fit_residuals.csv：是否符合摊薄形态。
6. 再判断长输出是否接近、TPOT 是否平台。
7. 最后看是否具备 token/prefill 事件证据，决定机制结论上限。

## 哪些事情没有替你完成

- 尚未读取或转换你的真实 aisbench 数据。
- 尚未确认你使用的 aisbench 版本、字段结构、单位、TPOT 定义和请求到达方式。
- 尚未产生真实结果、图表或分析结论。
- 未安装任何 Skill 到内部平台；不同平台的安装方式需按内部环境处理。

这些不是由模型猜测来补齐的事项，必须通过本包规定的第一、二阶段完成。

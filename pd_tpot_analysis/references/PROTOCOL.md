# 分析协议：从 aisbench 原始文件到可审计结论

## 1. 分开检验四个问题

不要一上来写“证明混部扰动被摊薄”。先分别回答：

- H1，现象：同一并发下，混部与分离的 TPOT 绝对差是否随输出变长缩小？
- H2，形态：差值是否符合有限开销摊薄的 `A/N + δ` 形态？
- H3，接近性：在已测长输出范围内，差异是否进入预先约定的业务容差？
- H4，机制：额外延迟是否确实发生在 prefill/decode 重叠窗口，并且累计影响不会随长度近似线性增长？

H1 不推出 H2，H2 不推出 H4，H3 不等于无限长度下严格相等。

特别的反例：两种部署的 TPOT 都随上下文变长而上升，但差值变小。此时支持差距缩小，不支持混部 TPOT 本身下降。

## 2. 第一步：盘点真实文件，不猜 aisbench 格式

### 2.1 给目录建立清单

用户提供路径后，只扫描该目录。不要自动扫描整块磁盘或其他项目。

记录：文件路径、扩展名、大小、修改时间、疑似角色、疑似实验条件、是否压缩、是否可能重复。

压缩包先只看成员清单，检查绝对路径和 `..` 路径穿越；解压到全新空目录。原始目录中的 Python、shell、notebook 或可执行文件不运行。

### 2.2 只读少量结构样例

每种文件结构选样例：
- 一个短输出 case。
- 一个最长输出 case。
- 一个高并发 case。
- 混部和分离至少各一个。
- 有失败/超时记录时选一个。

JSON：查看顶层类型、key、嵌套路径、数组长度和前几条记录。大 JSON 优先用独立脚本做结构摘要，不打印完整内容。
JSONL：看前几行和末几行；确认一行是否完整 JSON。
CSV：看表头、几行、行数、分隔符和单位。
日志：查配置段、请求 ID、指标定义、运行开始结束和错误段。

### 2.3 建立字段映射表

每一项至少包含：

```text
标准字段 | 原始文件类型 | 原始 JSON 路径/CSV 列
原始单位 | 转换公式 | 缺失处理 | 含义证据 | 已验证样例
```

必须解决的字段：mode、并发、目标输入/输出、实际输入/输出、run/repeat、请求状态、首末 token 时间或可信 decode 时间、预热、请求总数。

证据优先级：本次运行配置/实际记录 > 同版本实现或文档 > 用户确认 > 文件名推测。证据冲突先记录并回查，不任意挑一种。

### 2.4 覆盖检查

计划条件是：2 种部署 × 5 个并发 × 8 个输出长度 = 80 个条件，不含重复运行。

逐格标记：计划、发现、确认、缺失、存在额外配置、真实重复数。重复 run 不能充当新条件；同一次运行的多个导出文件不算重复。

## 3. 第二步：先审计可比性

### 3.1 三个最容易混淆的量

- 设定并发 C：发压器允许的在途请求数。
- 实际活跃 decode batch：某时刻真正参与 decode 的请求数。
- 请求总数 R：一次运行中发送了多少请求。

C=32 不代表 R=32，也不代表全程 batch=32。

### 3.2 负载方式如何影响机制

burst：一批请求，不补请求。若全部 prefill 在首 token 前完成，TTFT 可能增加，但首 token 后的 TPOT 未必存在 prefill 干扰。若有分批调度/长尾 prefill，则需要事件证据。

closed_loop：请求完成后补新请求。延长输出可能降低补入请求频率，这会改变 prefill/decode 比例。即使差距缩小，也可能是负载组成变化，不能简单称同一固定开销摊薄。

open_loop：固定到达率。总 prefill 压力未必降低；长输出会影响队列和实际并发，需记录到达率和饱和状态。

unknown：只允许描述趋势和模型一致性，不能解释干扰频率或固定扰动来源。

### 3.3 硬件和服务配置边界

本实验默认只回答“一机混部部署 vs 两机分离部署”。不能把架构差异与资源差异分离为因果结论。

不要把双机 TPOT 除以 2。TPOT 是延迟，不是线性成本。

可选另报整体吞吐、机器数归一化吞吐、资源成本，但必须单独定义；不要让这些指标替代原问题。

## 4. 第三步：重算、核对和质量检查

### 4.1 每个有效请求重算

```text
N_i = 实际输出 token 数 - 1
TPOT_i = decode_ms_i / N_i
```

必须是完整首 token 到末 token 的耗时。TTFT 中包含的 prefill 不可再计入 TPOT。

### 4.2 抽查至少这些情况

- 混部短输出、分离短输出。
- 混部长输出、分离长输出。
- 高并发和低并发。
- 实际输出短于目标的请求。
- 失败请求或 L<2 请求（如果存在）。

每类选实际存在的记录，打印来源、原始值、换算、计算结果。缺少某类说明“不存在/未提供”，不得制造记录。

### 4.3 必查质量项

1. 重复 run_id、重复 (run_id, request_id)。
2. 同一次运行是否被多个文件重复导入。
3. ms/s/us 单位及计时起终点是否一致。
4. NaN、Inf、负时长、时间倒置、L<2。
5. 目标长度与实际长度的分布；完整长度比例。
6. 实际输入长度是否仍为 512；prefix cache/输入复用是否一致。
7. 预热是否由真实配置/标记识别。
8. 每个 run 的成功、超时、失败、取消、未完成数量。
9. 运行是否完整结束；是否只记录已完成请求。
10. 输出 65536 是否超上下文限制、截断或触发内存容量状态变化。
11. 是否有抢占、重计算、换出、队列增长和批大小变化证据。
12. 工具 summary 与逐请求重算的口径差异。

报告 summary 差值，不能为对齐 summary 去修改原始值。不同口径不能强求相等。

## 5. 第四步：形成主比较表

对每个 analysis_group、C、目标 L 分别分析，不能先混合不同并发。

### 5.1 聚合顺序

先请求 → run，再独立 run → 条件。运行平均等权，避免某轮请求多而占更大权重。

```text
M(L,C) = 混部的运行级主指标的均值
D(L,C) = 分离的运行级主指标的均值
Δ(L,C) = M - D
R(L,C) = M / D - 1
```

R 的单位默认比例，乘 100 才是百分比。报告不要把 0.05 写成 0.05%。

### 5.2 E 的适用范围

```text
E(L,C) = Δ(L,C) × (L - 1)
```

只有两侧纳入估计的成功有效请求实际都输出同一个 L 时，才把 E 解释为对比意义上的额外 decode 耗时。

两侧实际长度不同、提前 EOS、长度分布不同时：
- 不直接乘目标长度后称额外耗时。
- 先报告实际长度分布及其差异。
- 可做明确标注的实际长度匹配/分层敏感性分析；这会改变估计对象，且按完成长度筛选可能产生选择偏差。
- 不用删除提前结束请求的方式悄悄让主结果更整齐。

E 接近常数符合固定额外耗时模型；E 近似随 N 线性增长意味着可能存在持续性差异；这些均不是单独的因果证据。

### 5.3 最小主表

```text
组、并发、目标输出、两侧重复数、两侧有效请求数
实际输出分布、失败率、两侧 TPOT、Δ、R
Δ/R 的置信区间（如可用）、E（如适用）
质量标记、来源 run_id
```

附带脚本会分别输出表，最终可连接生成展示表；不能丢掉质量标记。

## 6. 第五步：趋势和摊薄模型

### 6.1 先看现象

逐 C 回答：
- 混部 TPOT 是否总体降低？
- 分离 TPOT 是否也变化？
- Δ 是否缩小？
- R 是否缩小？
- 变化是否超出重复运行波动？

不要求每点单调；不使用 Spearman/P 值替代实际效应量。若使用趋势相关，只作为辅助描述，8 个长度点不能当大量独立实验。

### 6.2 再做形态模型

```text
N = L - 1
x = 1 / N
Δ = A × x + δ
```

- A 单位 ms：有限的额外 decode 耗时分量。
- δ 单位 ms/token：模型估计的持续差异，不是直接测量到的无限长度极限。
- 仅实际固定长度、计时口径一致、无未解释状态切换时使用。
- 附带脚本默认对条件均值做不加权拟合，属于形态诊断。不要把它包装成高精度推断。

必须同时看：
1. A、δ、拟合点数、R²、RMSE。
2. 每个长度的残差，是否有系统弯曲/跳变。
3. 与常差模型 `Δ = 常数` 的留一长度预测误差对比。
4. 去掉最短点、去掉最长点后 A/δ 是否大幅改变。
5. 预测在已测区间是否产生明显不合理值。

如果实际长度不足、无完整长度记录，脚本不强行拟合。先解释为什么不适用。

### 6.3 不同结果怎样解释

- A>0、δ小、残差无明显系统结构：符合有限额外开销摊薄。
- A>0、δ明显为正且稳定：有摊薄分量，但可能仍有持续差距。
- A≈0：不支持明显 1/N 摊薄分量。
- A<0：与预期方向相反，应检查数据和机制，不把 A 强行截断成 0。
- 长输出开始 Δ 回升：可能有长上下文/KV/调度状态改变；不能只拟合前半段后宣称全区间成立。
- δ负值：可能存在混部优势、分离开销或模型失配；不强行改为 0。

附带脚本不产生 A/δ 置信区间，因此不能仅凭输出称 δ 显著为正/为零。需要更强推断时，先明确 run 是否在同一 sweep/block 中相关，再按独立块 bootstrap 重拟合。无这类设计信息时，保持描述性。

不要用 `log(Δ)` 回归来强行检验 1/N：Δ 可以为零或负数，删掉这些点会产生选择偏差。

## 7. 第六步：不确定性与接近性

### 7.1 真正的重复单位

一个 run 内的请求共享机器、调度和背景负载，不是完全独立重复。ITL 更不是独立重复。

优先每条件至少 5 次独立运行；少量重复的区间仍不稳定。关键 case 可 10 次以上，依据成本和波动决定。

- 配对设计：同一时间块/同一输入集/预先安排的运行对，有证据才填 pair_id。两侧按 pair 一起重采样。
- 非配对设计：两侧独立重采样 run。
- 伪重复：同一运行多个导出文件、多个请求、多个 chunk，都不能算独立重复。
- 有跨 run 的同日/同 sweep 相关性时，应以独立块重采样；附带脚本不自动识别，报告必须说明限制。

附带脚本：每条件两侧各至少 5 个独立 run 才输出 percentile bootstrap 区间；默认 5000 次、固定种子。该门槛是工作流保护，不是统计充分性的保证。

### 7.2 如何判定接近

先定义容差 m，例如 5%，必须说明是预先确定还是事后选择。

```text
相对差 R = M / D - 1
业务接近区间 = [-m, +m]
```

如果某条件 R 的 95% bootstrap 置信区间全部位于容差内，可报告“95% 区间包含于预设容差”，作为该条件下接近性的证据。这里采用较保守的 95% 区间规则，不要误写成已执行参数式 TOST。

正式 TOST（双单侧等效性检验）需单独明确统计假设及尺度；常规 alpha=0.05 的 TOST 对应 90% 区间，而不是自动照搬本协议的 95% 区间。

区间跨出容差：证据不足或不接近，结合位置判断。差异检验不显著不是等效。

事后容差：只能写“探索性地进入某容差”，不能升级为预注册的确认性结论。不得把“预注册”开关打开来改变真实事实。

### 7.3 长输出平台与长输出接近不是一件事

长输出区间可预设为 16384/32768/65536，但首次看完结果才选择时必须标为探索性。

平台需明确标准，例如：长输出范围内混部 TPOT 最大相对变化不超过某容差，并评估不确定性。不能以“斜率不显著”认定平台。

检查：
- TPOT 本身是否平稳。
- Δ 是否平稳且足够小。
- R 是否落入容差。

若混部/分离同时上升但 Δ 缩小，报告“差距缩小”，不要报告“TPOT 已平稳”。

单点区间不自动提供全曲线的同时置信覆盖。若做大量筛选后强调个别点，应披露筛选及多重比较问题；全并发/全长区间结论须预先定义如何判定，不能挑点。

## 9. 第七步：机制验证

### 9.1 有逐 token + prefill 事件

1. 检查时间戳单位、时钟域、偏移和漂移。
2. 检查每请求 token 计数和实际输出一致。
3. 用真实事件标记 prefill/decode 重叠，不用 ITL 尖峰反向生成事件标签。
4. 看相同 token 位置/上下文长度、近似 batch 下，重叠与非重叠窗口的 ITL 差异。
5. 没有可比窗口时不要随便拿短输出 baseline 代替长输出 baseline。
6. 估算额外延迟的累计量及随输出长度的增长方式；保留负差，不用 `max(差值,0)` 造成系统性正偏。
7. 检查稳定非干扰段是否仍有持续性差异。
8. 检查 batch、KV 容量、抢占和通信事件是否共同解释尖峰。

### 9.2 只有 ITL

识别尖峰、段落和位置分布，但不归因 prefill。客户端 ITL 包含网络、缓冲和 chunking 的影响。

### 9.3 没有 ITL

机制结论止于“与有限额外开销摊薄模型一致/不一致”。写出补测，不臆造 profiler 证据。

## 10. 补测优先级

按现有证据缺口排序，不默认重跑全部 80 条：

1. 补齐配置、发压模式、单位和实际输出长度；这些优先于复杂统计。
2. 对关键短/中/长输出和高并发补独立重复，并随机化测试顺序、记录时间块。
3. 对反例或长输出拐点补服务端事件、KV/抢占/batch 观测。
4. 控制实验：已有 decode 流上注入次数/规模受控的 prefill，观测额外耗时是否有限；或改变注入次数，检验累计额外延迟是否随次数变化。
5. 可比 decode 资源下切换部署，或说明剩余资源混杂。

不要为了更像理想曲线而重跑后只保留好看的结果。

## 11. 最终报告模板

```text
标题：一机 PD 混部与两机 PD 分离的长输出 TPOT 对比

1. 一句话结论（限定并发、长度、部署、证据等级）
2. 实验与资源边界
3. 数据来源、实际覆盖、重复次数、缺失与失败
4. TPOT 定义、时间边界、实际长度与聚合口径
5. 各并发现象表：TPOT 趋势、Δ 趋势、R 趋势
6. 摊薄模型：A/δ、点数、残差、预测误差、敏感性
7. 长输出接近性：阈值来源、CI、是否预注册、支持范围
8. TPOT 是否平稳（单独回答，不能与接近性混写）
9. 机制证据：已观测/仅推测/缺失
10. 反例、混杂、幸存者偏差与不能推出的结论
11. 最小补测建议
12. 文件清单、版本、随机种子和复现命令
```

逐 C 的结论表至少包含：

```text
C | 有效长度/重复 | 混部 TPOT 是否下降 | Δ 是否缩小
是否符合 1/N 形态 | 长输出是否进入容差 | TPOT 是否平台
机制证据等级 | 反例/限制
```

证据等级：
- E0：单位、口径或可比性未确认。
- E1：描述性趋势，或重复不足。
- E2：有运行级不确定性，支持差距/接近性的量化判断。
- E3：模型形态、质量和敏感性检查一致，支持摊薄模型解释。
- E4：有事件对齐与控制实验，进一步支持具体干扰机制。

这些是报告组织标签，不是自动化统计显著性等级。

推荐措辞：

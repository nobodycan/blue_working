# 分阶段提示词：一次发送一段

用法：首次启动先按 START_HERE.md 操作。随后按阶段发送，不跳过验收。每轮都替换工作目录；上下文不足时只重新读必要章节、STATE.md 和上一阶段产物。

所有阶段共同约束：原始文件只读，内部数据不外传；未知不猜；反例保留；只在门禁通过后执行依赖步骤；公式使用纯文本。

## 阶段 0：冻结计划

```text
请读取 SKILL.md 的原则与阶段 0、PROTOCOL.md 第 1/3/7 节。
本轮只冻结分析计划，不看性能结果来选择阈值。

创建 analysis_plan.md，逐项填写：
1. 分析部署边界：一机混部 vs 两机分离，记录 decode 端资源是否可比。
2. 四个假设 H1/H2/H3/H4，分别需要什么证据。
3. 发压方式、请求总数、独立运行次数，未知就 unknown。
4. 主 TPOT 口径及选择依据；另一口径仅作敏感性分析。
5. 长输出区间、接近阈值、平台标准；标明预先确定/事后探索性/尚未确定。
6. 失败、超时、预热、实际长度偏差的处理规则。
7. 已有信息、缺口及只影响哪些分析。

若已经有人看过结果，不得声称本计划是严格预注册。
更新 STATE.md。不要输出性能结论，不要要求我先回答所有未知项才继续文件盘点。
```

验收：四个假设分开；阈值来源诚实；资源边界明确。

## 阶段 1：侦察和映射

```text
请读取 DATA_CONTRACT.md 和 PROTOCOL.md 第 2/3 节。
本轮只做文件清单、结构侦察、字段映射和配置审计。

先列原始目录内的文件，不执行其中脚本。
按混部/分离、短/长输出、低/高并发挑少量真实样例。
对 JSON 输出结构摘要，对 CSV 输出表头和少量记录，避免整文件塞入上下文。

创建：
- inventory.csv
- field_mapping.md
- coverage.csv（80 个计划条件，逐格记录确认情况和独立重复数）
- deployment_audit.md

field_mapping.md 对每个标准字段给出原始路径、单位、转换、缺失处理、含义证据、样例。
必须区分：目标输出/实际输出、并发/请求总数、请求/独立运行、summary/detail、token/chunk。
必须确认时间起终点，不能只看字段名。

如果只有汇总数据，声明切换受限分支，不从均值制造请求。
若关键口径未知，列出最小必要问题，同时完成不依赖该问题的盘点。
更新 STATE.md；本轮不拟合，不宣布推论成立。
```

验收：给出真实字段路径和样例；单位有证据；不只有“发现若干 JSON”。

## 阶段 2：转换和审计

```text
请读取 DATA_CONTRACT.md 全文、PROTOCOL.md 第 4 节。
使用已核实的 field_mapping.md，为真实结构编写转换器，不写基于猜测的通用解析器。
脚本放工作代码目录，原始路径通过参数传入，使用 python -I 运行。

依次做：
1. 明确一个原始文件对应一个 run 还是多个 run。
2. 确定权威请求来源，避免 summary/detail/log 重复导入。
3. 规范 run_id、request_id、repeat_id 和真实 pair_id；无配对就空。
4. 换算时间单位，保存来源与定位信息。
5. 保留失败、超时、预热、L<2 和未完成运行，不为了曲线删除记录。
6. 生成 runs.csv、requests.csv；如有 token 时间戳，另存 token_intervals.csv。
7. 转换器测试覆盖单位、真实结构变体、缺失、重复、失败、L=1、时间错误。
8. 按协议抽查短/长/高并发/长度异常的真实记录，展示完整手算。
9. 对比原始 summary 与重算，解释不同聚合口径。
10. 运行附带分析器的 self-test 和 validate，写 quality_report.md。

validate 非零退出码必须处理。不可改脚本容差、伪造字段、删反例来通过。
只有汇总数据时另写运行级受限适配，不调用要求逐请求输入的分析接口。
列出每条告警的解释、对后续结论的影响，更新 STATE.md。
```

验收：可追溯 CSV、真实抽查、测试通过、标准化校验通过；不是只有转换代码。

## 阶段 3：主分析

```text
请读取 PROTOCOL.md 第 5/7 节，检查阶段 2 门禁。
先运行附带分析器的主口径，再运行另一聚合口径敏感性分析，使用不同新目录。
没有第三方依赖需求，不要联网安装库。

逐个并发建立主表：两侧均值、独立重复数、失败率、实际长度、Δ、R、可用 CI、可用 E。
从 run_metrics.csv 保留运行间离散度和来源。
每个缺失 case 标明缺失，不插值当观测。
重复不足不补造 CI；请求数不能当独立重复数。
配对不完整时不能随意按排序凑对；说明并修复设计元数据，或者保持受限。

先写 descriptive_results.md，只描述观测与不确定性，不归因 prefill。
两种聚合口径若结论不同，检查实际长度与加权影响，不择优选结果。
更新 STATE.md。
```

验收：每并发都有表；均值旁有重复、失败和长度信息；相对差单位正确。

## 阶段 4：模型、接近性和图表

```text
请读取 PROTOCOL.md 第 6/7/8 节，检查阶段 3 产物。
本轮严格按顺序：现象 → 形态 → 接近性 → 平台。

1. 每并发分别回答混部 TPOT、分离 TPOT、绝对差、相对差的变化。
2. 读取 fit_diagnostics.csv 和 fit_residuals.csv，不重复发明统计实现。
3. 检查 A/δ、点数、残差、留一长度误差、去最短/最长点敏感性。
4. A/δ 没有参数区间，只能描述；不把 δ 接近 0 的点估计当严格证明。
5. 检查长输出的 R 区间是否完整进入容差，说明阈值事前/事后；无 CI 则证据不足。
6. 按单独平台标准检查 TPOT 是否平稳；不能把“与分离接近”写成“TPOT 已平稳”。
7. 按图表规格生成 A/B/C/D；E 的质量信息至少做表。每图输出对应 CSV。
8. 图表缺失点显示为缺失，不能用 0 填充；CSV 比例转百分比须乘 100。
9. 依赖不具备时输出绘图数据与详细规格，说明尚未绘制，不擅自安装。

写 hypothesis_results.md，逐并发给支持/不支持/证据不足，列所有反例。
不能为了提高 R² 删除长输出拐点。模型不适用就明确说明。
更新 STATE.md。
```

验收：趋势、模型、容差、平台四种结论没有混为一谈；图表可追溯。

## 阶段 5：机制证据

```text
请读取 PROTOCOL.md 第 9/10 节。
先确认是否确实存在逐 token 时间戳和 prefill 事件；不要假设有。

若两者都有：核对真实 token 边界与时钟，独立用事件标记干扰窗口，检查 batch/上下文混杂，量化累计额外延迟。
若只有 ITL：描述尖峰和段落，不声称其必然来自 prefill。
若只有 TPOT：明确机制未被直接验证，只评价是否与摊薄模型一致。

特别检查 burst 中 prefill 是否已全部进入 TTFT，closed_loop 中长输出是否降低补请求频率。
没有证据不能写“有限固定扰动”，没有控制实验不能写因果已证明。
输出 mechanism_evidence.md：观测事实、模型解释、竞争解释、缺口、最小补测。
不重新运行真实压测或修改机器配置，除非我另行授权。
更新 STATE.md。
```

验收：将可观测事实、模型假设和因果解释分开。

## 阶段 6：最终报告和反向检查

```text
请读取 PROTOCOL.md 第 11/12 节以及全部阶段的结果文件。
按模板生成 report.md，并写一段可直接阅读的中文摘要。

必须有 5 个并发的结论表，分别回答：
- 混部 TPOT 是否下降；
- 与分离差距是否缩小；
- 是否符合摊薄形态；
- 长输出是否进入容差；
- TPOT 是否平稳；
- 是否有 prefill 机制证据。

每个答案只允许来自已生成的结果，缺失就写缺失。
逐项执行 12 节自检，核对每个数字和来源，纠正任何把比例当百分比、把请求当重复的错误。
反向寻找一个最不支持用户假设的条件，必须在报告中讨论；若无有效反例，也说明检查了哪些范围。
保留一机/两机、实际长度、失败率、负载模型和样本量限制。

最终列出已完成、受限、未完成；未画图不能说已画，未验证机制不能说已证实。
更新 STATE.md 为最终状态，附全部复现命令。
```

验收：结论有范围、有证据等级、有反例、有缺口；没有绝对化的“推论正确”。

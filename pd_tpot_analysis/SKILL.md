# PD TPOT 分析 Skill

## 适用任务

分析昇腾 A2 上的 PD 实验：输入目标 512，输出目标 512/1024/2048/4096/8192/16384/32768/65536，并发目标 1/4/8/16/32；混部一台机器，分离两台机器。

这些是计划值，不是已经确认的数据事实。实际配置、实际 token 数、缺失 case 必须从数据验证。

本 Skill 可由支持 Skill 的工具加载，也可以直接粘贴给内部模型。不得依赖特定模型厂商、联网能力或特定工具名。全程使用可直接阅读的纯文本公式。

## 工作原则：必须执行

1. 目标是检验假设，不是证明用户一定正确。保留反例、失败、超时和不支持的并发档位。
2. 不知道就写 `unknown`；不得猜测 aisbench 版本、字段名、字段单位、并发模型、TPOT 定义或部署配置。
3. 每次只执行一个阶段。每阶段输出“执行了什么、产物路径、检查结果、阻塞项、下一步”。通过门禁后才能进入下一阶段。
4. 非阻塞的不确定性不停止其他工作；只阻塞依赖它的分析。举例：没有逐 token 数据不影响汇总趋势分析，但禁止声称已验证扰动来源。
5. 原始文件只读。生成的脚本、归一化文件和结果放在原始目录之外。输出使用新目录，不覆盖旧结果。
6. 内部数据不得上传外网，不调用外部模型，不擅自安装依赖，不运行原始数据目录内的脚本。
7. Python 处理外来文件时使用 `python -I 脚本绝对路径 ...`，工作目录和脚本目录均不使用原始数据目录。
8. 先读真实数据的目录清单、样例和元数据，再写格式转换器。禁止套用记忆中的 aisbench JSON 结构。
9. 同一个请求在 summary/detail/log 中重复出现，只能保留一份权威请求记录，其他用于核对，不能叠加。
10. 不用并发数替代请求数，不用请求数替代独立实验重复次数，不从汇总平均值伪造请求记录。
11. 不删除异常值来改善曲线，不按是否符合假设挑选长度或并发。事后定义的阈值和区间必须标为探索性。
12. 不把“差异不显著”写成“等效”，不把模型截距点估计接近 0 写成“已证明无限长度收敛”。
13. 若只拿到汇总数据，走受限分析分支；不得强行生成逐请求 CSV 并运行要求逐请求数据的脚本。
14. 文件名只能用于生成待确认的配置候选，不作为配置的最终证据。

## 阶段 0：冻结分析问题和计划

输入：用户说明、可用配置、原始数据路径。

操作：
- 创建 `analysis_plan.md`，逐项记录：主指标、部署对照边界、负载模式、独立重复单位、接近阈值、长输出范围、失败率处理原则。
- 主指标通常选“每请求 TPOT 的均值，再对独立运行等权平均”；同时保留 token 加权口径作为诊断。若工具口径不同，先解释再选择，不可混用。
- 接近阈值若未知，先保留未预注册状态；可以做 2%/5%/10% 敏感性分析，但必须标为事后探索性。
- 检查是否能取得逐请求数据、逐 token 数据、服务端 prefill 事件。
- 明确实际并发是 burst、closed_loop、open_loop 还是 unknown。

产物：`analysis_plan.md`。

门禁：原始数据路径未给出时，不编造数据，不扫描无关目录；先交付计划和待补清单。负载模式未知不阻塞描述性分析，但阻塞固定扰动机制结论。

## 阶段 1：文件盘点和字段侦察

操作：严格执行协议第 2 节。只读取必要样例，不一次性把巨型文件塞进上下文。

产物：
- `inventory.csv`：文件清单、类型、大小、配置候选、是否重复。
- `field_mapping.md`：原始路径、字段含义、原始单位、转换规则、证据、未知项。
- `coverage.csv`：80 个计划条件的已发现/已确认/缺失/重复状态。
- `deployment_audit.md`：硬件、模型、并行策略、调度、KV cache、发压方式。

门禁：关键时间单位或 TPOT 口径未确认时，不进入 TPOT 数值比较。只有汇总数据时明确切换受限分支。

## 阶段 2：标准化与质量检查

操作：
1. 按数据契约生成 `runs.csv` 和 `requests.csv`。需要逐 token 分析时另建 `token_intervals.csv`。
2. 为真实格式编写转换器；输入路径通过参数传入；输出到新目录。
3. 给转换器编写小型测试：单位换算、两种数组/行式结构、重复记录、缺失字段、失败请求、L=1、时间不合法。
4. 随机抽查和定向抽查原始记录，逐条展示 TPOT 计算过程。
5. 运行附带的标准化分析器的 `validate` 子命令；失败则修正映射或原始问题，不修改阈值绕过报错。
6. 核对原始 summary 与逐请求重算值；差异须定位到聚合口径、单位、过滤规则或实现定义。

产物：归一化 CSV、转换脚本、转换测试、`quality_report.md`、验证 JSON。

门禁：重复键、非有限值、时间倒置、配置串组、关键元数据缺失未解决时，不发布对应组的数值结论。若仅有工具 TPOT 而无其定义证据，不能伪造成规范 decode_ms。

## 阶段 3：计算主结果

操作：
- 运行附带 `scripts/analyze_normalized.py analyze`，明确传入主指标。
- 每个并发单独分析；每个输出长度分别比较；先得到运行级指标，再得到条件级指标。
- 检查失败率、实际输出分布、实际活跃 batch 资料、运行间波动。
- 不足 5 个独立重复时，附带脚本不产生置信区间；只写描述性趋势。
- paired 对照必须来自真实配对设计；不得用请求编号、随意排序或相同数字 repeat_id 伪造配对。

产物：运行指标表、条件指标表、差值表、质量告警。

门禁：每个结果可追溯到 run_id；无重复次数冒充样本量；主指标和诊断指标明确区分。

## 阶段 4：检验现象、形态和接近性

依次做，不可跳步：
A. 现象：TPOT 是否变化？绝对差是否缩小？相对差是否缩小？二者不一致时解释。
B. 形态：检验 `Δ = A / (L - 1) + δ`；看残差、留一长度预测误差和端点敏感性；不能只看 R²。
C. 接近性：在预先指定的长输出区间，查看相对差置信区间是否完全进入预先指定容差。事后阈值仅探索性。
D. 反例：单独列出不支持的并发、长度、异常运行，不能用总平均掩盖。

必须遵守协议第 5—8 节。附带脚本的拟合只提供描述性形态诊断，不提供 δ 的置信区间，不自动证明极限或因果。

产物：`hypothesis_results.md` 和协议规定的图表。绘图依赖不可用时输出图表数据和绘图规格，不擅自联网安装。

门禁：所有“接近”结论指明容差、置信水平、样本量和测试范围；所有模型结果指明可用长度点数。

## 阶段 5：验证机制或明确证据缺口

- 有 token 时间戳和 prefill 事件：按协议第 9 节对齐时钟、识别 chunk/token 边界、定位干扰窗口、量化额外延迟。
- 有 token 时间戳但无事件：只能识别尖峰和稳定段，不能把尖峰直接归因 prefill。
- 只有逐请求/汇总 TPOT：只能说“符合摊薄模型”，不能说“证实是 prefill 干扰导致”。
- 无新增实验权限时，列补测建议，不能伪造 profiler 证据。

产物：`mechanism_evidence.md`。

## 阶段 6：最终交付与自检

按协议第 11 节模板生成 `report.md`。必须包括每个并发的结论、失败/缺失情况、硬件差异、支持和反对证据、证据等级、补测优先级、复现命令。

运行附件脚本自测，并保留输出。最终用协议第 12 节清单逐条自检。

禁止输出：
- “已证明混部在任意长输出时等于分离”。
- “两者 P > 0.05，因此没有差异”。
- “所有 case 都支持假设”，但实际只展示有利子集。
- “处理成功”，但没有字段映射、质量报告和可复现命令。

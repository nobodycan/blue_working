# 一键运行：按你们现有的模型参数 + HTTP 采集

使用 [oneclick_aisbench_profile.py](oneclick_aisbench_profile.py)，它是独立单文件、Python 标准库实现。**原 AISBench/wrapper 发压不变，采集采用 `--profiler-config` + `/start_profile`、`/stop_profile`，不使用 msprof attach，也不需要 PID、SSH 或动态 socket。**

## 1. 模型启动时配置 P/D

正确拼写是 `--profiler-config`，不是 `--profiler-cofnig`。在现有、已验证的 P 启动命令中添加/合并：

```bash
--profiler-config '{"profiler":"torch","torch_profiler_dir":"/data/pd_profile/torch/P","torch_profiler_with_stack":false,"torch_profiler_with_memory":false}'
```

D 使用独立目录：

```bash
--profiler-config '{"profiler":"torch","torch_profiler_dir":"/data/pd_profile/torch/D","torch_profiler_with_stack":false,"torch_profiler_with_memory":false}'
```

不改原 TP/EP、MTP、图模式、cache 或 connector。你们若已经这样启动且参数正确，就无需重启。没配置时需按原部署流程重新启动服务使参数生效；总控脚本不自动重启模型。

0.30.0rc2 内置 NPU wrapper 使用 torch_npu.profiler；这条路径不依赖 `PROFILING_MODE=dynamic`，也不需要命令行 msprof attach。[精确版本官方指南](https://github.com/vllm-project/vllm-ascend/blob/v0.30.0rc2/docs/source/developer_guide/performance_and_debug/service_profiling_guide.md)

## 2. 只填一次配置

在已有 AISBench Python 环境的 Linux 客户端，保存这一个脚本并执行：

```bash
python3 oneclick_aisbench_profile.py --init profile.json
```

若以前生成过 msprof 版 profile.json，先保留它，给 HTTP 版使用新文件名，例如 `profile_http.json`；不要把旧版 PID/SSH 配置直接当成新配置。

编辑新配置，主要填写：

| 字段 | 实际值 |
|---|---|
| `tools_dir` | 已成功使用的 aisbench_auto_tools_prefix 目录 |
| `dataset_pattern` | 原 full 数据路径，可用 `{C}`、`{N}`；例 `/data/bench/full_C{C}_N{N}.jsonl` |
| `targets.P.base_url` | P 实例根 API 地址，如 `http://P_IP:8100`，不带 `/v1` |
| `targets.D.base_url` | D 实例根 API 地址，如 `http://D_IP:8200` |
| 各侧 `metrics_url` | 从客户端能访问的该实例 `/metrics`，用于请求活动触发 |
| 各侧 `profile_dir` | 与本侧模型启动的 torch_profiler_dir 一致；只是记录，不会通过 HTTP 改路径 |
| `cache_note` | 原 cache/prefix 状态和跨轮准备方法 |

模型名、proxy 地址、tokenizer、API 模板和推理鉴权继续沿用原工具配置；采集开关必须直连 P/D，不能默认 proxy 会转发。

若采集接口需要 Bearer 鉴权，将 key 放进客户端 `PROFILE_API_KEY` 环境变量；metrics 单独需要鉴权时使用 `PROFILE_METRICS_API_KEY`。不要在地址或命令行明文放 key。

## 3. 检查，再从 C=1 开始

```bash
python3 oneclick_aisbench_profile.py --config profile.json --concurrencies 1 --check
python3 oneclick_aisbench_profile.py --config profile.json --concurrencies 1 --execute
```

`--check` 只做本地数据检查和 GET `/health`、`/openapi.json`，不发推理或采集开关。它检查 OpenAPI 中是否包含两个 POST 接口。如果你们明确关闭了 OpenAPI，可把该侧 `check_openapi` 设为 false；此时预检查只证明服务 health，接口能力到实际 POST 时才验证。

C=1 验证成功后运行原五档：

```bash
python3 oneclick_aisbench_profile.py --config profile.json --execute
```

固定普通模式、128K/1K、C=1/2/4/8/16、N=4C。默认每档分 P、D 两轮诊断，共 10 轮。`--roles P` 或 `--roles D` 可只采一侧；`--mode both` 额外增加每档 OFF 基线，共 15 轮。原4C数据文件行数须精确匹配；脚本不会通过 `--data_num` 假装裁剪了文件。

默认分侧采集是同工况不同轮，不是同一请求的 P/D 精准对齐。需要两侧同轮窗口时，已有 `scripts/profile_window.py` 可以同时控制两侧；先确认不同 device 与采集约束，并另存该实验。

## 4. 自动化顺序与你们怎么对应

1. 保存本轮配置和数据哈希，可选执行你已有的 cache 准备命令/公共 prefix 预热。
2. 通过原 AISBench/wrapper 发 128K/1K 请求，仍走原 PD proxy。
3. 观察目标实例 running gauge，等请求到达并按配置延迟触发。
4. `POST 本侧/start_profile` → 收集指定秒数 → `POST 本侧/stop_profile`。
5. 等 AISBench 正常结束，检查原生 Success/Failed Requests，保存报表、HTTP 开关时间与输出目录记录。

P 默认活动后立即采，D 默认再等 2 秒，窗口默认 5 秒；可调整 `capture_delay_s`、`capture_seconds`。**running>0 不等于纯 D，也不保证短窗覆盖整次 128K prefill**，阶段仍需看 trace。

你们也可以按官方顺序先 start_profile，再发 AISBench，最后 stop_profile；脚本默认先发压再短时采集，是为了减少数据初始化或长空闲的采集。两种都是同一内置 profiler 控制方式。

## 5. 输出和后处理

客户端结果默认在 `runs/oneclick_http/RUN_ID/`，包括 `case.json`、`events.json`、`http_controls.json`、AISBench 原生报告和最终 `index.csv`。

NPU 文件由服务进程写到模型启动配置的 P/D 容器路径。HTTP 控制脚本不通过网络搬运 trace、不临时修改保存目录，也不凭 200 响应断言“已经有有效 NPU 数据”。根据 HTTP 时间窗核对本轮新生成的 `*_ascend_pt`，避免混入旧数据。

若停止后尚未得到可视化结果，在服务对应的 torch_npu/CANN 环境解析实际目录：

```bash
python3 - <<'PY'
from torch_npu.profiler.profiler import analyse
analyse('/data/pd_profile/torch/P/替换为实际本轮目录_ascend_pt')
PY
```

或使用本包 `scripts/analyze_profiles.py`。已有有效解析输出时无需重复；Insight 查看 `trace_view.json` / 相应目录或 DB，以实际导出格式为准。

## 6. 保持原实验条件

公共 prefix 预热用 `prefix_dataset` 单独配置，不纳入正式 4C；cache 准备可在 `before_case_argv` 中调用已有命令。没有配置 hook 不代表 cache 自动重置。相同 full 数据反复重放可能让 suffix 变热，脚本不自动声称 OFF/ON 的 cache 等价。

原始数据、实际 token、失败数、P/D 各 rank 和时间线仍需核验。`HTTP_CAPTURE_STOPPED_VERIFY_SERVER_TRACE` 表示 HTTP 控制完成，不表示 kernel、纯 D 或所有 rank 已验证。

异常时脚本尝试 stop_profile 并停止它自己发起的客户端进程，不结束模型服务。若停止状态不明，则中止后续档位，先检查本侧 `/stop_profile` 和服务日志。不要同时运行另一采集器或其他 wrapper。

先前的 `oneclick_aisbench_msprof.py` 仅保留为其他场景的 attach 版本，本次使用这里的 HTTP 版。

# 官方来源与版本核验

检索日期：2026-10-26。下面区分 **版本化证据**、**通用工具文档** 和 **本包实验建议**。main/latest 会继续变化，目标机安装源码优先于网页标题。

## A. 已核实的精确版本

### S1 · vLLM-Ascend v0.30.0rc2 服务采集指南

[官方版本化文档源码](https://github.com/vllm-project/vllm-ascend/blob/v0.30.0rc2/docs/source/developer_guide/performance_and_debug/service_profiling_guide.md)

支持本包的核心路径：以 `--profiler-config` 开启能力，使用 HTTP 接口控制，再解析/查看输出；PD 两个实例要独立配置和控制。普通 PD 示例代理不转发采集开关，应直连 P/D API。具体代理有不同能力，不能把这个限制推广到所有代理。

官方在线页面：[Service Profiling Guide](https://docs.vllm.ai/projects/ascend/en/main/developer_guide/performance_and_debug/service_profiling_guide.html)。本包采用简短转述与原创步骤，没有复制整篇文档。

### S2 · v0.30.0rc2 NPU profiler wrapper 源码

[TorchNPUProfilerWrapper](https://github.com/vllm-project/vllm-ascend/blob/v0.30.0rc2/vllm_ascend/profiler/torch_npu_profiler.py)

已核实该 tag 的设置：CPU/NPU 活动、Level1、PipeUtilization、TEXT 导出；memory/modules 受 vLLM profiler 配置控制。该 wrapper 对 `msmonitor_use_daemon` 与 torch profiler 同启有冲突检查。若目标镜像有补丁，以现场源码为准，不套用不存在的 level CLI 参数。

### S3 · v0.30.0rc2 worker 源码

[NPUWorker](https://github.com/vllm-project/vllm-ascend/blob/v0.30.0rc2/vllm_ascend/worker/worker.py)

核实 worker 的 profile 控制和实际 wrapper 接入。采集能力在 worker 进程内，客户端本身开启 profiler 不等同于采到了服务端 NPU。

### S4 · vLLM v0.30.0 ProfilerConfig

[ProfilerConfig](https://github.com/vllm-project/vllm/blob/v0.30.0/vllm/config/profiler.py)

核实 profiler、输出路径、stack、memory 等字段。本包使用绝对输出路径。配置有字段不等于 NPU wrapper 会以相同方式使用全部字段；需同时看 S2。

### S5 · vLLM v0.30.0 服务压测源码

[serve.py](https://github.com/vllm-project/vllm/blob/v0.30.0/vllm/benchmarks/serve.py)

核实压测入口、warmup、保存详细结果、输出字段和模型别名等参数。客户端版本若不同，脚本会先核对安装 CLI 的帮助。结果汇总不凭自己重新计时替代官方 duration。

### S6 · vLLM v0.30.0 随机数据生成

[datasets.py](https://github.com/vllm-project/vllm/blob/v0.30.0/vllm/benchmarks/datasets/datasets.py)

核实随机输入/输出长度、range ratio 和 prefix 参数。固定采样长度仍需实际分词/服务端 token 计数验证，尤其代理不提供 tokenize 接口时。

## C. 这些是本包的实验设计建议

“从 C=1、2、4 开始”“先收 3–5 秒”“正式档位重复 3 次”“优先 1K/128 再 8K/1K”等，是为了降低入门成本提出的方案，不是官方硬性规定，也不代表某型号的容量保证。

本包给出候选瓶颈和对照方法，**没有声称通过统计证实某工具在行业中使用最多**，也没有根据模型名推算你的设备卡数或峰值性能。

## D. 仍需现场确认

- 用户给定 I800 的具体产品/芯片/板卡信息，以 `npu-smi` 和设备资料为准。
- 一台还是多台物理机，P/D 各用多少卡，是否使用互斥的物理 device。
- vLLM 主包、插件、CANN、torch_npu、镜像是否为对应构建或自定义补丁。
- 原版 Flash、0731 或其他权重修订；MTP 是否开启。
- 代理是否提供 completions、流式返回、tokenize 和指标接口。
- 各 rank 的实际导出文件、时钟基准和 KV 事件覆盖程度。
